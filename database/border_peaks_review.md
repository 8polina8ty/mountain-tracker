# Border Peaks — Discovery and Verified Membership

## Architecture
Bounded offline pipeline `scripts/border-peaks/` reuses `scripts/osm-import/BOUNDARY_DATA.md` (geoBoundaries `gbOpen` ADM1, pinned `9469f09` 2023-12-12, WGS84 `Polygon`/`MultiPolygon`, no simplification) as detailed boundary source. `mountains` (~364k, `id bigint`, `name/name_de`, `latitude/longitude`, `height`, `country_code` primary) and `mountain_countries(mountain_id,country_code,is_primary)` (backfilled) are read-only inputs. Discover stage scans mountains with a 5km buffer spatial index (grid, bbox pre-filter, deterministic, resumable `--resume`) against border segments; only `CONFIRED` rows with explicit evidence become `mountain_countries` secondaries. Existing `get_my_country_mountain_progress/list_my_country_mountains` use `EXISTS (select 1 from mountain_countries where mountain_id=m.id and country_code=profile.country_code)` so new memberships appear automatically, counted `distinct` once per country.

## Boundary data source
- **Selected for Alps initial scope:** William & Mary geoLab geoBoundaries `gbOpen` ADM1 high-precision single-country files (DE/AT/CH/IT/FR/SI/LI), commit `9469f09`, `data/osm/boundaries/alps-admin.geojson` local normalized, per-feature `source/sourceUrl/license/licenseUrl/attribution/version` preserved. File is 111MB, 82 features (`AT/CH/DE/FR/IT/LI/SI`), each `Polygon`/`MultiPolygon` with holes.
- **ADM1 vs international contract:** ADM1 contains many internal admin boundaries (e.g., Bavaria–Baden-Württemberg, Tyrol–Salzburg) that are **not** international. A point near an internal ADM1 edge must not be treated as border candidate. Pipeline now distinguishes: it builds segments from all exterior rings + holes and groups by `countryCode`; a candidate is marked `hasInternationalGeometry:false → REJECTED` unless it is within 5km of both its primary country's edge **and** a foreign country's edge (coincident international border). For production hardening, an ADM0 or specifically curated international border dataset is preferable to inferring coincidence from ADM1 polygons; the current logic is a conservative filter that keeps internal edges rejected. Source/version/license/attribution remain preserved per feature, no silent substitution.
- **Licensing/attribution:** per-source (DE dl-de/by-2-0, AT CC BY-SA 2.0, CH swisstopo OGD, IT CC BY 3.0, FR Etalab 2.0, SI CC BY 4.0, LI ODbL 1.0); combined file stays local `.gitignore`, not redistributed without full attribution/license review. See `scripts/osm-import/BOUNDARY_DATA.md`.
- **Accuracy vs Natural Earth:** Natural Earth generalized (~1:10m, ~5000m error) may be useful for coarse discovery but is **insufficient** for summit-level membership; pipeline rejects `boundaryPrecisionMeters>500` to REVIEW. OSM geometries themselves are not legal proof — we require dual-country `supporting_external_reference` (e.g., `OSM:summit:1 dual AT-DE border` or surveyed record), not summit identity alone.
- **CRS:** WGS84 `[lon,lat]` GeoJSON, no reprojection; distances via haversine for endpoints and equirectangular local tangent `pointToSegmentMeters` for interiors (~1% error <20km at 47°N), handles wraparound 180/-180, high latitude 80°N, invalid geometry → `Infinity`.

## Classification & accuracy
- **Stages:** `CANDIDATE` → `GEOMETRICALLY_SUPPORTED` → `EXTERNALLY_VERIFIED` → `APPROVED` (reviewer). Pipeline `classification` is `CONFIRMED/REVIEW/REJECTED` but `evidence_type` tracks stage: `CANDIDATE` for REVIEW distance-only, `GEOMETRICALLY_SUPPORTED` for spatial match without dual proof, `EXTERNALLY_VERIFIED` only with `supporting_external_reference` containing `dual`/`border` dual attribution, `APPROVED` only after explicit `approved_by/approved_at`.
- **CONFIRMED:** summit on detailed **international** shared border within `min(30, (coordAccuracy+boundaryPrecision)*0.5)` (tolerance 80m → 30m), `boundary_source` present, `supporting_external_reference` is dual-country evidence (not just `OSM:summit:id`), `hasInternationalGeometry=true`, not disputed/conflicting, `boundaryPrecision<=500`.
- **REVIEW:** near-border 50–200m, summit-only reference, missing provenance, `hasInternationalGeometry=false` (internal ADM1), generalized boundary `>500m`, conflicting/disputed, triple-border, holes/MultiPolygon ambiguity.
- **REJECTED:** >200m or internal ADM1 only, or `hasInternationalGeometry=false`.
- **Why proximity alone is insufficient:** summit-only OSM node does not prove country membership; massif ≠ summit, lakes/ridgelines, 50–200m GPS error, generalized polygons, enclaves, disputed status — all force manual review. Export gate enforces `EXTERNALLY_VERIFIED + approved_by/approved_at/boundary_source_id`.

## Evidence per candidate
`mountain_id,mountain_name,latitude,longitude,height,primary_country_code,candidate_country_code,classification,boundary_source/boundary_source_id/dataset_version/license,distance_to_boundary_meters,supporting_external_reference,reason,review_notes,existing_memberships` → `data/border-peaks/candidates.jsonl` + `confirmed/review/rejected.jsonl` + `summary.json` (counts, `per_country_pair`, `countries_covered`). Synthetic `fixtures.jsonl` (10 cases: Zugspitze AT+DE, inside, 150m REVIEW, confirmed border, triple, duplicate name, conflict, missing coord, existing, XK) are clearly synthetic.

## Review process & SQL export (hardened)
Only `CONFIRMED` with `evidence_type=EXTERNALLY_VERIFIED` and **separate manifest** `data/border-peaks/approved-manifest.jsonl` may be exported via `scripts/border-peaks/export-approved.ts data/border-peaks/confirmed.jsonl data/border-peaks/approved-manifest.jsonl database/generated/mountain_countries_reviewed_batch.sql`. Each manifest entry is `{candidate_hash, mountain_id, candidate_country_code, approved_by, approved_at, evidence_url}` where `candidate_hash` is SHA256 of canonical candidate JSON (sorted keys of mountain_id/name/lat/lon/height/primary/candidate/boundary_source/_id/_version/distance/supporting_reference/evidence_type). Editing `candidate_country_code` or distance invalidates hash → export fails closed. `REVIEW`/`REJECTED` cannot be exported, missing `dual` evidence blocks, distance >100m blocks. SQL is `INSERT ... ON CONFLICT DO NOTHING` `is_primary=false` (never overwrites primary, never `UPDATE mountains.country_code`). Deployment order: `mountain_countries.sql` → `border_seed.sql` → `mountain_countries_rpc_patch.sql` → new batch after manual `border_peaks_review.md` approval. Rollback: delete specific `(mountain_id,country_code)` rows. Real discovery CLI fails closed if `data/osm/boundaries/alps-admin.geojson` missing/invalid — synthetic stubs are test-only (`data/border-peaks/fixtures.jsonl`).

## Performance
Batches (`--limit`), spatial index, `bboxForPoint` 5km pre-filter avoids O(364k×boundaries) full scan; memory bounded by writing JSONL streaming + `GridIndex` cells. Dry-run `--dry-run` logs `summary.json` without files. Initial scope `DE/AT/CH/FR/IT` (~ Alps), `--country` filter, `--region`, `--resume` via line count, deterministic haversine.

## Import pipeline integration
Existing OSM bulk import still writes single `mountains.country_code`. Future point: after `mountains` upsert, also `insert into mountain_countries(mountain_id,country_code,is_primary,source) values (...,'osm_import') on conflict do nothing`. Secondary membership remains manual/reviewed, not auto-inferred.

## Known limitations
- Synthetic stubs now only for unit tests; production path uses real `alps-admin.geojson` with `pointToSegmentMeters` (segment interior, endpoint, holes via exterior/hole rings, MultiPolygon disjoint territories, high latitude, wraparound). Triple-border and enclaves generate REVIEW, not auto multi-assign; ADM1 coincidence heuristic is conservative — a true ADM0 international dataset would be preferable for global coverage (Natural Earth insufficient, OSM ADM0 not yet pinned).
- `XK` allowed as mountain data `^[A-Z]{2}$` but residence `XK` still rejected via `is_residence_country`.
- Global ranking unchanged; no MapLibre change; no huge dataset download in this phase (global 364k not run).
